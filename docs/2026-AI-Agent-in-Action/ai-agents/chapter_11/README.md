# 11장: OpenAI Assistants API와 에이전트 통합

## 개요

이 장에서는 OpenAI Assistants API를 활용하여 대화형 AI 어시스턴트를 구축하는 방법을 다룬다. 기본적인 API 호출부터 스트리밍 응답 처리, Gradio와 Streamlit을 이용한 웹 UI 구축, 그리고 Nexus 프레임워크 기반의 플래너/실행기 패턴까지 단계적으로 확장해 나간다. 또한 파일 감시 기반의 자동 단위 테스트 생성, 웹캠 이미지 캡처 등 실용적인 응용 사례도 포함되어 있다.


## 파일 설명

### 핵심 API 계층

| 파일 | 설명 |
|------|------|
| `assistants_api.py` | OpenAI Assistants API를 래핑하는 클래스. 어시스턴트 CRUD, 스레드 생성, 메시지 전송, 스트리밍 실행 등 모든 API 호출을 캡슐화한다. |
| `assistants_utils.py` | `AssistantEventHandler`를 확장한 이벤트 핸들러 구현. 텍스트 델타, 코드 인터프리터 입출력, 이미지 파일 저장 등 스트리밍 이벤트를 처리하며, 로그와 이미지 목록을 관리한다. |

### 기본 예제

| 파일 | 설명 |
|------|------|
| `assistants_api_response.py` | Assistants API의 가장 기본적인 사용법. 어시스턴트를 생성하고, 스레드에 메시지를 추가한 뒤 `create_and_poll`로 동기 응답을 받는 예제이다. |
| `assistants_api_streaming.py` | `AssistantEventHandler`를 상속하여 스트리밍 방식으로 응답을 받는 예제. 텍스트 델타와 코드 인터프리터 출력을 실시간으로 콘솔에 출력한다. |

### 웹 UI (Gradio)

| 파일 | 설명 |
|------|------|
| `gradio_chat.py` | Gradio의 `ChatInterface`와 OpenAI Chat Completions API를 결합한 간단한 스트리밍 챗봇. Assistants API를 사용하지 않는 기본 비교 예제이다. |
| `gradio_streaming_chat.py` | Gradio `ChatInterface`에 Assistants API의 스트리밍을 연결한 예제. 스레드가 대화 히스토리를 관리하므로 별도의 히스토리 전달이 필요 없다. |
| `gradio_assistants_chatbot.py` | 완전한 기능을 갖춘 Gradio 기반 어시스턴트 챗봇. 어시스턴트 관리 패널, 멀티모달 입력(텍스트/이미지), LaTeX 렌더링, 코드 인터프리터 로그 표시 등을 지원한다. |
| `gradio_assistants_panel.py` | 어시스턴트 관리를 위한 Gradio UI 컴포넌트. 어시스턴트 목록 조회, 새 어시스턴트 생성, 기존 어시스턴트 수정/삭제, 모델/도구/온도 등 파라미터 설정 기능을 제공한다. |

### 웹 UI (Streamlit)

| 파일 | 설명 |
|------|------|
| `chatgpt_clone_streaming.py` | Streamlit으로 구현한 ChatGPT 클론. Chat Completions API의 스트리밍을 `st.write_stream`으로 출력하며, 세션 상태로 대화 히스토리를 관리한다. |
| `streamlit_manage_assistants.py` | Streamlit으로 구현한 어시스턴트 관리 페이지. 어시스턴트 선택, 생성, 수정, 삭제 기능을 제공하는 관리 도구이다. |

### Nexus 프레임워크

| 파일 | 설명 |
|------|------|
| `basic_nexus_planner.py` | Nexus 플래너의 핵심 코드 모음 (예제 11.3~11.5). 퓨샷 프롬프트로 JSON 계획을 생성하는 플래너 프롬프트, `create_plan` 함수, `execute_plan` 함수를 포함한다. `for-each` 특수 함수를 통한 반복 처리도 지원한다. |
| `nexus_models.py` | Nexus 프레임워크의 데이터 모델 정의. Peewee ORM을 사용하여 에이전트 사용량 추적, 채팅 참가자, 스레드, 메시지, 지식 저장소, 메모리 저장소, 사고 템플릿 등의 테이블을 정의한다. 대화형/의미론적/절차적/일화적 메모리 유형과 추론/평가 사고 템플릿 초기 데이터도 포함한다. |

### 응용 예제

| 파일 | 설명 |
|------|------|
| `unit_test_assistant.py` | 파일 변경을 감시하여 자동으로 단위 테스트를 생성하는 어시스턴트. `watchdog` 라이브러리로 디렉터리를 모니터링하고, 파이썬 파일이 변경되면 코드 인터프리터를 통해 테스트를 생성한다. |
| `webcam.py` | OpenCV를 사용한 웹캠 이미지 캡처 유틸리티. 일정 간격으로 웹캠 프레임을 타임스탬프가 포함된 파일명으로 저장한다. 비전 기반 에이전트의 입력 데이터 수집에 활용할 수 있다. |

## 주요 개념

- **Assistants API 생명주기**: 어시스턴트 생성 -> 스레드 생성 -> 메시지 추가 -> 실행(Run) -> 응답 수신의 흐름을 이해한다.
- **동기 vs 스트리밍 응답**: `create_and_poll`을 통한 동기 방식과 `AssistantEventHandler` 기반 스트리밍 방식의 차이와 각각의 적합한 사용 시나리오를 다룬다.
- **이벤트 핸들러 패턴**: `on_text_created`, `on_text_delta`, `on_tool_call_created`, `on_tool_call_delta`, `on_image_file_done` 등 각 이벤트에 대한 커스텀 처리 방법을 학습한다.
- **코드 인터프리터 통합**: 어시스턴트에 `code_interpreter` 도구를 연결하고, 코드 실행 결과와 생성된 이미지를 처리하는 방법을 다룬다.
- **웹 UI 프레임워크 비교**: Gradio와 Streamlit을 사용한 챗봇 UI 구현 방법을 비교하며, 각 프레임워크의 상태 관리 방식을 학습한다.
- **Nexus 플래너/실행기 아키텍처**: LLM 기반의 계획 수립(Planning)과 계획 실행(Execution) 분리 패턴을 학습한다. 퓨샷 프롬프트로 JSON 계획을 생성하고, 실행기가 이를 순차적으로 처리한다.
- **메모리 시스템**: 대화형(Conversational), 의미론적(Semantic), 절차적(Procedural), 일화적(Episodic) 네 가지 메모리 유형과 각각의 요약/증강 전략을 이해한다.
- **사고 템플릿(Thought Templates)**: 추론(reasoning), 평가(evaluation), 메모리 증강, 지식 증강 등의 재사용 가능한 프롬프트 템플릿 체계를 다룬다.
- **파일 감시 자동화**: `watchdog`을 활용한 파일 시스템 모니터링과 코드 변경 시 자동 테스트 생성 파이프라인을 구현한다.


## 학습 교훈

1. **스레드 기반 대화 관리의 이점**: Assistants API의 스레드는 서버 측에서 대화 히스토리를 관리하므로, 클라이언트에서 별도로 메시지 목록을 유지할 필요가 없다. 이는 상태 관리를 단순화하지만, 스레드 ID를 세션 간에 유지해야 하는 책임이 생긴다.

2. **스트리밍은 사용자 경험의 핵심이다**: 동기 방식(`create_and_poll`)은 구현이 간단하지만, 응답 지연이 길어질 수 있다. 스트리밍을 사용하면 사용자가 응답이 생성되는 과정을 실시간으로 확인할 수 있어 체감 대기 시간이 크게 줄어든다.

3. **이벤트 핸들러 설계 시 부수 효과를 분리하라**: `assistants_utils.py`의 `EventHandler`처럼 로그 수집, 이미지 저장 등의 부수 효과를 핸들러 내부에 캡슐화하면, UI 코드와 데이터 처리 로직을 깔끔하게 분리할 수 있다.

4. **계획 수립과 실행의 분리는 에이전트의 신뢰성을 높인다**: Nexus 플래너 예제에서 볼 수 있듯이, LLM이 계획을 JSON으로 출력하고 별도의 실행기가 이를 처리하는 패턴은 디버깅과 검증을 용이하게 한다. 계획의 각 단계를 독립적으로 검증할 수 있기 때문이다.

5. **퓨샷 프롬프트는 구조화된 출력의 품질을 결정한다**: `basic_nexus_planner.py`에서 여러 예시를 통해 JSON 계획의 형식을 LLM에게 가르친다. 예시의 다양성과 정확성이 곧 생성되는 계획의 품질로 직결된다.

6. **메모리 유형의 적절한 선택이 에이전트 성능을 좌우한다**: 네 가지 메모리 유형(대화형, 의미론적, 절차적, 일화적)은 각각 다른 정보를 추출하고 요약한다. 에이전트의 목적에 맞는 메모리 유형을 선택하는 것이 중요하며, 잘못된 선택은 불필요한 정보 축적이나 핵심 정보 누락으로 이어질 수 있다.

7. **프로토타이핑 프레임워크의 선택은 목적에 따라 달라진다**: Gradio는 컴포넌트 조합과 실시간 스트리밍에 강점이 있고, Streamlit은 데이터 중심의 대시보드와 세션 상태 관리에 직관적이다. 두 프레임워크 모두 빠른 프로토타이핑에 적합하지만, 복잡한 UI가 필요한 경우 Gradio가 더 유연하다.

8. **자동화 파이프라인은 에이전트의 실용적 가치를 보여준다**: `unit_test_assistant.py`는 파일 변경 감지와 AI 테스트 생성을 결합한 실용적 사례로, 에이전트가 개발 워크플로우에 직접 통합될 수 있음을 보여준다. 디바운싱(debounce) 처리 등 실제 운영 환경에서의 고려 사항도 함께 다룬다.
