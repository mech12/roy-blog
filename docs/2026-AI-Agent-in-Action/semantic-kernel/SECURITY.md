## 보안

Microsoft는 GitHub 조직을 통해 관리되는 모든 소스 코드 리포지토리를 포함하여, 소프트웨어 제품 및 서비스의 보안을 매우 중요하게 생각합니다.

[Microsoft의 보안 취약점 정의](https://aka.ms/security.md/definition)에 해당하는 보안 취약점을 Microsoft 소유 리포지토리에서 발견했다고 판단되면, 아래 설명된 방법으로 보고해 주세요.

## 보안 이슈 보고

**공개 GitHub 이슈를 통해 보안 취약점을 보고하지 마세요.**

대신, Microsoft 보안 대응 센터(MSRC)에 보고해 주세요: [https://msrc.microsoft.com/create-report](https://aka.ms/security.md/msrc/create-report).

24시간 이내에 응답을 받으실 수 있습니다. 만약 응답을 받지 못하신 경우, [https://msrc.microsoft.com/report/vulnerability](https://msrc.microsoft.com/report/vulnerability/)에서 취약점 보고서의 Activity 탭 하단에 있는 메시지 기능을 사용하여 후속 조치를 취하거나, [https://msrc.microsoft.com/create-report](https://aka.ms/security.md/msrc/create-report) 하단의 안내에 따라 이메일로 연락해 주세요. 추가 정보는 [microsoft.com/msrc](https://www.microsoft.com/msrc) 또는 MSRC의 [이슈 보고 FAQ 페이지](https://www.microsoft.com/en-us/msrc/faqs-report-an-issue)에서 확인할 수 있습니다.

가능한 이슈의 특성과 범위를 더 잘 이해할 수 있도록 아래 요청 정보를 (제공 가능한 만큼) 포함해 주세요:

- 이슈 유형 (예: 버퍼 오버플로, SQL 인젝션, 크로스 사이트 스크립팅 등)
- 이슈 발현과 관련된 소스 파일의 전체 경로
- 영향을 받는 소스 코드의 위치 (태그/브랜치/커밋 또는 직접 URL)
- 이슈를 재현하는 데 필요한 특수 설정
- 이슈를 재현하기 위한 단계별 지침
- 개념 증명 또는 익스플로잇 코드 (가능한 경우)
- 공격자가 이슈를 악용할 수 있는 방법을 포함한 이슈의 영향

이 정보는 보고서를 더 신속하게 분류하는 데 도움이 됩니다.

버그 바운티를 위해 보고하시는 경우, 더 완전한 보고서는 더 높은 바운티 보상에 기여할 수 있습니다. 활성 프로그램에 대한 자세한 내용은 [Microsoft 버그 바운티 프로그램](https://aka.ms/security.md/msrc/bounty) 페이지를 방문해 주세요.

## 선호 언어

모든 커뮤니케이션은 영어로 진행되는 것을 선호합니다.

## 정책

Microsoft는 [협력적 취약점 공개(Coordinated Vulnerability Disclosure)](https://aka.ms/security.md/cvd) 원칙을 따릅니다.
