# Semantic Kernel 책임 있는 AI FAQ

## Microsoft Semantic Kernel이란 무엇인가요?
Microsoft Semantic Kernel은 C#, Python, Java 등의 언어로 작성된 애플리케이션에 AI 모델을 통합하는 것을 용이하게 하기 위해 설계된 경량 오픈 소스 개발 키트입니다.

개발자가 AI 에이전트를 구축하고, 비즈니스 프로세스를 자동화하며, 코드를 최신 AI 기술과 연결하는 것을 지원하는 효율적인 미들웨어입니다. 이 시스템에 대한 입력은 텍스트 데이터부터 구조화된 명령까지 다양하며, 자연어 응답, 함수 호출 및 기타 실행 가능한 데이터를 포함한 다양한 출력을 생성합니다.

## Microsoft Semantic Kernel은 무엇을 할 수 있나요?
기본 기능을 바탕으로, Microsoft Semantic Kernel은 다음과 같은 여러 기능을 제공합니다:
-	AI 에이전트 개발: 사용자 입력에 기반하여 특정 작업이나 상호작용을 수행할 수 있는 에이전트를 생성할 수 있습니다.
-	함수 호출: AI 모델 출력에 기반하여 함수를 호출함으로써 코드 실행을 자동화할 수 있습니다.
-	모듈형 및 확장 가능: 개발자는 플러그인과 다양한 사전 구축된 커넥터를 통해 기능을 향상시킬 수 있으며, 추가 AI 서비스 통합에 유연성을 제공합니다.
-	멀티 모달 지원: 커널의 아키텍처를 통해 기존 애플리케이션을 음성 및 비디오와 같은 모달리티를 지원하도록 쉽게 확장할 수 있습니다.
-   필터링: 개발자는 필터를 사용하여 애플리케이션을 모니터링하고, 함수 호출을 제어하거나 책임 있는 AI를 구현할 수 있습니다.
-   프롬프트 템플릿: 개발자는 Handlebars, Liquid 또는 기본 제공 Semantic Kernel 형식을 포함한 다양한 템플릿 언어를 사용하여 프롬프트를 정의할 수 있습니다.

## Microsoft Semantic Kernel의 의도된 용도는 무엇인가요?
Microsoft Semantic Kernel의 의도된 용도는 다음과 같습니다:
- 	프로덕션 준비 애플리케이션: 고급 AI 모델 기능을 활용할 수 있는 소규모부터 대규모 엔터프라이즈 솔루션 구축.
-	비즈니스 프로세스 자동화: 조직 내 워크플로 및 작업의 빠르고 효율적인 자동화 지원.
- 	AI 서비스 통합: 빠른 개발을 위해 클라이언트 코드를 다양한 사전 구축된 AI 서비스 및 기능과 연결.


## Microsoft Semantic Kernel은 어떻게 평가되었나요? 성능 측정에 어떤 지표를 사용하나요?
Microsoft Semantic Kernel의 지표는 다음과 같습니다:
-	통합 속도: 텔레메트리를 기반으로 AI 모델을 통합하고 기능적 출력을 시작하는 데 걸리는 시간으로 평가합니다.
-	성능 일관성: 텔레메트리를 기반으로 시스템의 신뢰성을 검증하기 위한 측정을 수행합니다.


## Microsoft Semantic Kernel의 한계는 무엇인가요?
Semantic Kernel은 대규모 언어 모델(LLM)과 통합하여 기존 애플리케이션에 AI 기능을 추가할 수 있게 합니다.
LLM에는 다음과 같은 고유한 한계가 있습니다:
-	맥락 오해: 시스템이 특히 복잡한 맥락을 포함하는 미묘한 요청에서 어려움을 겪을 수 있습니다.
-	LLM 출력의 편향: 학습 데이터의 역사적 편향이 모델 출력에 의도치 않게 영향을 미칠 수 있습니다.
	-	사용자는 다음과 같은 방법으로 이러한 문제를 완화할 수 있습니다:
		-	명확하고 명시적인 쿼리를 작성합니다.
		-	AI 생성 출력을 정기적으로 검토하여 편향이나 부정확성을 식별하고 수정합니다.
        -   LLM이 응답의 근거로 사용할 수 있도록 프롬프트 시 관련 정보를 제공합니다.
-   모든 LLM이 모든 기능을 균일하게 지원하지는 않습니다. 예: 함수 호출(function calling).
Semantic Kernel은 지속적으로 발전하며 새로운 기능을 추가하고 있으므로:
-   아직 개발 중인 컴포넌트가 있습니다. 예: 비디오 및 분류와 같은 일부 모달리티 지원, 특정 벡터 데이터베이스용 메모리 커넥터, 특정 AI 서비스용 AI 커넥터.
-   아직 실험적인 컴포넌트가 있으며, 이들은 명확히 표시되어 있고 변경될 수 있습니다.

## Microsoft Semantic Kernel의 효과적이고 책임 있는 사용을 위한 운영 요소 및 설정은 무엇인가요?
최적의 사용을 위한 운영 요소 및 설정은 다음과 같습니다:
-	사용자 정의 구성 옵션: 사용자는 출력 스타일이나 상세도와 같은 특정 애플리케이션 요구에 맞게 시스템 매개변수를 조정할 수 있습니다.
-	안전한 운영 매개변수: 시스템은 정의된 입력 복잡성 및 길이 범위 내에서 최적으로 작동하여 신뢰성과 안전성을 보장합니다.
-	실시간 모니터링: 예상치 못한 패턴이나 오작동을 신속하게 감지하기 위해 시스템 동작을 정기적으로 모니터링해야 합니다.
-	책임 있는 사용을 보장하기 위해 Prompt Shield와 같은 RAI 및 안전 도구를 필터와 함께 활용하세요.

### 플러그인 및 확장성

#### 플러그인이란 무엇이며 Microsoft Semantic Kernel은 이를 어떻게 사용하나요?
플러그인은 다른 서비스와 통합하여 Microsoft Semantic Kernel의 기능을 강화하고 확장하는 API 호출입니다. 내부에서 개발하거나 서드파티 개발자가 개발할 수 있으며, 사용자가 요구 사항에 따라 켜고 끌 수 있는 기능을 제공합니다. 커널은 OpenAPI 사양을 지원하여 개발 팀 내에서 플러그인을 쉽게 통합하고 공유할 수 있습니다.

#### Microsoft Semantic Kernel은 플러그인에 어떤 데이터를 제공할 수 있나요? Microsoft Semantic Kernel 플러그인은 어떤 권한을 가지나요?
플러그인은 운영에 필요한 필수 사용자 정보에 접근할 수 있습니다:
-	입력 컨텍스트: 시스템에 발행된 쿼리 및 명령과 직접 관련된 정보.
-	실행 데이터: 사용자 개인정보 보호 기준을 준수하는 한, 이전 작업의 결과 및 성능 지표. 개발자는 플러그인 권한에 대한 제어권을 유지하며, 플러그인이 접근하거나 전송할 수 있는 정보를 선택하여 데이터 보호 프로토콜을 준수합니다.
-   Semantic Kernel은 개발자가 RAI 솔루션과 통합할 수 있는 필터를 지원합니다.

#### Microsoft Semantic Kernel을 플러그인과 함께 사용할 때 어떤 문제가 발생할 수 있나요?
발생할 수 있는 잠재적 문제는 다음과 같습니다:
-	호출 실패: 잘못 트리거된 플러그인이 예상치 못한 출력을 초래할 수 있습니다.
-	출력 오정보: 플러그인 처리 오류가 부정확하거나 오해를 불러일으키는 결과를 생성할 수 있습니다.
-	종속성 호환성: 외부 종속성의 변경이 플러그인 기능에 영향을 줄 수 있습니다. 이러한 문제를 예방하기 위해, 플러그인을 최신 상태로 유지하고 안정성 및 정확성을 위해 구현을 철저히 테스트하시길 권장합니다.

#### AI를 다룰 때, 개발자는 사용하는 AI 플랫폼에서 콘텐츠 조정을 활성화할 수 있으며, 책임 있는 경계와 가이드라인을 정의하는 기능을 포함하여 사용되는 프롬프트에 대한 완전한 제어권을 가집니다. 예를 들어:
-	Azure OpenAI를 사용할 때, 기본적으로 서비스에는 핵심 모델과 함께 작동하는 콘텐츠 필터링 시스템이 포함됩니다. 이 시스템은 프롬프트와 완성 모두를 유해한 콘텐츠의 출력을 감지하고 방지하기 위한 분류 모델 앙상블을 통해 실행합니다. 콘텐츠 필터링 시스템 외에도, Azure OpenAI 서비스는 해당 제품 약관을 위반할 수 있는 방식으로 서비스를 사용하는 것을 시사하는 콘텐츠 및/또는 행동을 감지하기 위한 모니터링을 수행합니다. 필터 구성은 조정할 수 있으며, 예를 들어 "낮은 심각도" 콘텐츠도 차단하도록 설정할 수 있습니다. 자세한 내용은 여기를 참조하세요.
-	개발자는 Azure AI Content Safety를 통합하여 텍스트 및 이미지를 포함한 유해한 사용자 생성 및 AI 생성 콘텐츠를 감지할 수 있습니다. 이 서비스에는 템플릿과 사용자 정의 워크플로가 포함된 대화형 Studio 온라인 도구가 포함됩니다. 자세한 내용은 여기를 참조하세요.
-	OpenAI를 사용할 때 개발자는 OpenAI Moderation을 통합하여 문제가 있는 콘텐츠를 식별하고 필터링과 같은 조치를 취할 수 있습니다. 자세한 내용은 여기를 참조하세요.
-	기타 AI 제공업체는 콘텐츠 조정 및 조정 API를 제공하며, 개발자는 이를 Node Engine과 통합할 수 있습니다.

#### 컴포넌트 시퀀스가 실행될 때, 비결정적 동작 사용으로 인해 추가적인 위험/실패가 발생할 수 있습니다. 이를 완화하기 위해 개발자는 다음을 수행할 수 있습니다:
원하지 않는 결과를 방지하기 위해 각 컴포넌트에 안전 장치와 경계를 구현합니다.
시스템 상태에 대한 제어와 인식을 유지하기 위해 사용자에게 출력을 추가합니다.
멀티 에이전트 시나리오에서는 사용자의 응답을 요청하는 지점을 구축하여 사용자 참여를 보장하고 멀티 에이전트 루핑으로 인한 원하지 않는 결과의 가능성을 줄입니다.
