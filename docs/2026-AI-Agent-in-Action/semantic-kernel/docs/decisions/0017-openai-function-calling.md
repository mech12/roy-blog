# OpenAI 함수 호출 지원

## 맥락 및 문제 설명

OpenAI Chat Completions API의 [함수 호출](https://platform.openai.com/docs/guides/gpt/function-calling) 기능은 개발자가 모델에 함수를 설명하고, 모델이 주어진 프롬프트에 대한 응답으로 호출할 함수와 적절한 인수를 지정하는 JSON 객체를 출력할지 결정하도록 합니다. 이 기능은 `/v1/chat/completions` 엔드포인트에 대한 두 가지 새로운 API 매개변수를 통해 활성화됩니다:

- `function_call` - auto(기본값), none, 또는 호출할 특정 함수
- `functions` - 모델에 제공되는 함수의 JSON 설명

모델에 제공되는 함수는 시스템 메시지의 일부로 주입되며 입력 토큰으로 요금이 청구/계산됩니다.

이 기능을 지원하는 OpenAI 채팅 완성 모델과 함께 SK를 사용할 때 이 기능에 대한 지원을 제공해 달라는 커뮤니티 요청이 여러 건 있었습니다.

## 결정 요인

- OpenAI 전용 기능을 위한 코어 커널 변경을 최소화합니다
- 요청에 긴 함수 설명 목록을 포함하는 것에 대한 비용 우려
- 모델이 반환한 함수를 자동으로 실행하는 것에 대한 보안 및 비용 우려

## 검토한 옵션

- 인터페이스 수정을 _포함하여_ 채팅 완성 엔드포인트를 통한 함수 전송/수신 지원
- 인터페이스 수정 _없이_ 채팅 완성 엔드포인트를 통한 함수 전송/수신 지원
- 함수 호출 기능을 중심으로 플래너 구현

## 결정 결과

선택한 옵션: "인터페이스 수정 _없이_ 채팅 완성 엔드포인트를 통한 함수 전송/수신 지원"

이 옵션에서는 기존 요청 설정 객체를 활용하여 모델에 함수를 전송합니다. 앱 개발자가 포함할 함수를 제어하며 함수 결과의 유효성 검증 및 실행을 담당합니다.

### 결과

- 좋음, 코어 커널에 대한 호환성 파괴 변경을 방지하기 때문
- 좋음, OpenAI 전용 기능이 OpenAI 커넥터 패키지에 한정되기 때문
- 좋음, 앱이 모델에 제공되는 함수를 제어할 수 있기 때문(SK 외부 함수 포함)
- 좋음, 향후 플래너와의 통합 옵션을 열어두기 때문
- 보통, 앱 개발자가 결과 함수의 유효성 검증 및 실행을 해야 하기 때문
- 나쁨, 이 기능을 사용하고 함수 결과에 접근하는 방법이 명확하지 않기 때문

## 옵션별 장단점

### 채팅 완성 인터페이스 수정을 _포함하여_ 함수 전송/수신 지원

이 옵션은 `IChatCompletion` 및 `IChatResult` 인터페이스를 업데이트하여 함수 정보를 제공하고 접근하기 위한 매개변수/메서드를 노출합니다.

- 좋음, 함수 호출 기능을 사용하기 위한 명확한 경로를 제공하기 때문
- 좋음, 앱이 모델에 제공되는 함수를 제어할 수 있기 때문(SK 외부 함수 포함)
- 보통, 앱 개발자가 결과 함수의 유효성 검증 및 실행을 해야 하기 때문
- 나쁨, 코어 커널 추상화에 호환성 파괴 변경을 도입하기 때문
- 나쁨, OpenAI 전용 기능이 코어 커널 추상화에 포함되어 다른 모델 제공자가 무시해야 하기 때문

### 함수 호출 기능을 중심으로 플래너 구현

외부 함수 호출 조율은 SK의 플래닝 개념에 적합합니다. 이 접근 방식에서는 함수 호출 결과를 받아 앱 개발자가 실행할 수 있는 계획(SK의 ActionPlanner와 유사)을 생성하는 플래너를 구현합니다.

- 좋음, 계획 결과를 생성하면 앱 개발자가 선택된 함수를 쉽게 실행할 수 있기 때문
- 나쁨, 함수를 실행하려면 커널에 등록되어야 하기 때문
- 나쁨, 어떤 플래너를 언제 사용해야 하는지에 대한 혼란을 야기하기 때문

## 추가 참고 사항

커널에 등록된 OpenAI 모델이 반환한 함수를 자동으로 호출하는 것의 장단점에 대해 많은 논의와 토론이 있었습니다. 이 동작과 그 영향에 대한 미해결 질문이 여전히 많기 때문에, 초기 구현에 이 기능을 포함하지 않기로 결정했습니다. 이 옵션을 계속 탐색하고 향후 업데이트에 포함할 수 있습니다.
