# Semantic Kernel 함수는 인터페이스 또는 추상 기본 클래스를 사용하여 정의

## 맥락 및 문제 설명

Semantic Kernel은 함수를 나타내는 추상화를 정의해야 합니다. 즉, AI 오케스트레이션의 일부로 호출할 수 있는 메서드입니다.
현재 이 추상화는 `ISKFunction` 인터페이스입니다.
이 ADR의 목표는 Semantic Kernel의 장기적 목표를 충족하기 위해 이것이 최선의 추상화인지 결정하는 것입니다.

## 결정 요인

- 추상화는 나중에 새로운 기능을 추가할 수 있도록 확장 가능**해야 합니다**.
- 추상화의 변경은 소비자에게 호환성 파괴 변경을 초래**해서는 안 됩니다**.
- 현재로서는 소비자가 자체 `SKFunction` 구현을 제공해야 하는지 명확하지 않습니다. 이를 허용하면 Semantic Kernel에 새로운 기능을 추가할 때 문제가 발생할 수 있습니다. 예: 새로운 훅 유형을 정의하면 어떻게 될까요?

## 검토한 옵션

- `ISKFunction` 인터페이스
- `SKFunction` 기본 클래스

### `ISKFunction` 인터페이스

- 좋음, 구현이 임의의 클래스를 확장할 수 있기 때문
- 나쁨, 기본 구현의 동작만 변경할 수 있고 고객 구현이 호환되지 않을 수 있기 때문
- 나쁨, 고객이 이 인터페이스를 구현하는 것을 방지할 수 없기 때문
- 나쁨, 인터페이스 변경이 소비자에게 호환성 파괴 변경이 되기 때문

### `SKFunction` 기본 클래스

- 좋음, 인터페이스 변경이 소비자에게 호환성 파괴 변경이 **되지 않기** 때문
- 좋음, 클래스 생성자를 `internal`로 만들어 유효한 사용 사례를 파악할 때까지 확장을 방지할 수 있기 때문
- 좋음, 향후 기본 구현을 쉽게 변경할 수 있기 때문
- 나쁨, 구현이 `SKFunction`만 확장할 수 있기 때문

## 결정 결과

선택한 옵션: "`SKFunction` 기본 클래스", 일부 기본 구현을 제공할 수 있고 해당 사용 사례를 더 잘 이해할 때까지 새로운 SKFunctions 생성을 제한할 수 있기 때문입니다.
