# 호환성 깨짐(Breaking Changes) 가이드라인

## 컨텍스트 및 문제 설명

.Net에서는 잘 알려진 [다이아몬드 의존성 문제](https://learn.microsoft.com/en-us/dotnet/standard/library-guidance/dependencies#diamond-dependencies)로 인해 호환성 깨짐 변경을 반드시 피해야 합니다. 같은 패키지의 서로 다른 버전 간 호환성 깨짐 변경은 런타임에 버그와 예외를 유발합니다.

## 결정 요인

호환성 깨짐 변경은 다음 상황에서만 허용됩니다:

- 실험적 기능 업데이트 시, 즉 새로운 사실을 알게 되어 실험적 기능의 설계를 수정해야 하는 경우.
- 우리 의존성 중 하나가 피할 수 없는 호환성 깨짐 변경을 도입한 경우.

모든 호환성 깨짐 변경은 명확하게 문서화되어야 하며, 반드시 릴리스 노트에 포함하고 가능하면 마이그레이션 가이드 블로그 포스트도 작성해야 합니다.

- 릴리스 노트에 포함될 수 있도록 PR 설명에 호환성 깨짐 변경에 대한 상세한 설명을 포함합니다.
- Learn Site 마이그레이션 가이드 문서를 업데이트하고, 호환성 깨짐 변경이 포함된 릴리스와 동시에 게시합니다.

그 외의 모든 경우에는 호환성 깨짐 변경을 피해야 합니다. 의존성의 변경을 수용하거나 새로운 기능을 도입해야 하는 상황이 있을 수 있습니다. 예를 들어:

- 보안 이슈나 심각한 버그(예: 데이터 손실)를 발견한 경우.
- 의존성 중 하나가 대규모 호환성 깨짐 변경을 도입한 경우, 예: 새로운 OpenAI SDK 도입.
- 현재 구현에서 심각한 제한을 발견한 경우, 예: AI 서비스가 새로운 기능을 도입한 경우.

이러한 경우에는 해당 API를 사용 중단(obsolete)으로 표시하고 새로운 권장 패턴으로의 마이그레이션 경로를 문서화할 것입니다.
이에 대한 예시로 새로운 OpenAI .Net SDK로의 전환이 있습니다.
이 전환 기간 동안 고객이 마이그레이션할 수 있도록 새 API와 이전 API가 모두 지원되는 기간이 있을 것입니다.

## 결정 결과

선택된 옵션: 잘 알려진 다이아몬드 의존성 문제로 인해 .Net에서 호환성 깨짐 변경을 반드시 피해야 합니다.
