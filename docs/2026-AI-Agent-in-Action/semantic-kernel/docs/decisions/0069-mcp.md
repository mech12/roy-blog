# Model Context Protocol 통합

## 맥락과 문제 설명

[MCP](https://modelcontextprotocol.io/introduction)는 AI 모델 상호작용의 표준으로 빠르게 세력을 얻고 있으며, Semantic Kernel은 이 트렌드를 활용하기에 좋은 위치에 있습니다. MCP를 통합함으로써, 다른 AI 시스템 및 도구와의 플랫폼 상호운용성을 향상시켜 개발자가 여러 모델과 서비스를 활용하는 애플리케이션을 더 쉽게 구축할 수 있게 합니다.

이 ADR은 MCP 개념과 Semantic Kernel 개념 간의 매핑을 정의하며, Semantic Kernel에서 MCP를 구현하기 위한 로드맵을 제공합니다. MCP가 활발히 개발 중이므로, 새로운 개념이 추가되거나 개념의 실제 구현이 변경되면 이 문서를 업데이트해야 합니다.

## 설계

첫 번째 상위 수준 개념은 `server`(서버) 대 `host`(호스트)입니다. 서버는 하나 이상의 기능을 모든 호스트에 사용 가능하게 만들고, 호스트는 클라이언트를 사용하여 서버에 연결하며, 애플리케이션이 서버의 기능을 소비할 수 있게 합니다. 호스트는 여러 서버의 클라이언트가 될 수 있고, 서버는 여러 호스트에 의해 호스팅될 수 있습니다.

## 설계 - 호스트로서의 Semantic Kernel

이는 Semantic Kernel이 호스트 역할을 하여 서버의 기능을 사용할 수 있기를 원한다는 것을 의미합니다. 이는 MCP SDK 클라이언트를 사용하여 서버에 연결하고 해당 서버의 기능을 노출하는 플러그인을 만들어 수행합니다.

### 개념 매핑 - (MCP)호스트로서의 Semantic Kernel
| MCP 개념 | Semantic Kernel 개념 | 설명 |
| ----------- | ---------------------- | ----------- |
| [Server](https://modelcontextprotocol.io/docs/concepts/architecture) | Plugin | 서버는 관련된 함수의 집합으로 노출되므로 플러그인에 매핑됩니다. |
| [Resources](https://modelcontextprotocol.io/docs/concepts/resources) | 불명확 | 리소스는 매우 일반적인 개념이므로 어떤 하나의 SK 개념에는 맞을 수 있지만 전부는 아닙니다. 추가 조사가 필요합니다. |
| [Prompts](https://modelcontextprotocol.io/docs/concepts/prompts) | 외부 프롬프트 렌더링/함수 호출 | 프롬프트는 서버 개발자가 사용자에게 해당 서버를 활용하기 위한 더 쉬운 진입점을 제공하기 위해 만들 수 있는 기능으로, 정의된 매개변수로 채워지는 단일 문장이거나 특정 결과를 시작하기 위해 설계된 대화를 시뮬레이션하는 일련의 메시지일 수 있습니다. 이는 PromptTemplate의 렌더링 단계에 매핑되지만, 서버가 렌더링을 수행하고 SK는 이를 소비합니다. 출력은 PromptMessages 목록(대략 ChatMessageContents 목록에 해당)이어야 하며, 이를 LLM에 보내 완성할 수 있지만 이것이 어떻게 작동해야 하는지는 불명확합니다. |
| [Tools](https://modelcontextprotocol.io/docs/concepts/tools) | Function | 도구는 서버 개발자가 사용자에게 서버의 특정 기능을 활용할 수 있게 만드는 기능입니다. 이는 Semantic Kernel의 함수에 매핑되며, 가장 일반적인 사용 방법은 함수 호출을 통한 것이므로 잘 매핑됩니다. listChanged 이벤트 처리를 포함해야 합니다. |
| [Sampling](https://modelcontextprotocol.io/docs/concepts/sampling) | get_chat_message_content | 샘플링은 서버가 클라이언트를 통해 LLM 완성을 요청할 수 있게 하는 강력한 MCP 기능으로, 보안과 개인정보를 유지하면서 정교한 에이전트 동작을 가능하게 합니다. 즉, 서버가 SK 호스트에 메시지를 보내고 SK 호스트가 LLM을 호출하는 것을 의미합니다. MCP와 SK `PromptExecutionSettings` 및 서비스 셀렉터 간의 `ModelPreferences` 및 기타 세부사항 매핑이 필요합니다. |
| [Roots](https://modelcontextprotocol.io/docs/concepts/roots) | 사용 가능한 컨텍스트에 따라 다름 | Roots는 서버가 작동할 수 있는 경계를 정의하는 MCP의 개념입니다. 클라이언트가 서버에 관련 리소스와 위치에 대해 알려주는 방법을 제공하므로, SK는 현재 컨텍스트의 `roots`를 사용하는 서버에 보내야 합니다. 특정 컨텍스트에 따라 달라지며, 예를 들어 .Net용 FileIOPlugin을 사용할 때 이를 사용할 수 있습니다. Python에서는 현재 이것이 없습니다. |
| [Transports](https://modelcontextprotocol.io/docs/concepts/transports) | 다른 플러그인 구현 | SK는 모든 전송을 지원하고 그 차이를 추상화해야 합니다. 이는 플러그인이 모든 전송을 사용할 수 있어야 하고, SK 호스트가 구성 변경만으로 모든 전송을 사용할 수 있어야 함을 의미합니다. |
| [Completion](https://spec.modelcontextprotocol.io/specification/2025-03-26/server/utilities/completion/) | 미매핑 | MCP의 완성은 입력 중 사용자 입력을 완성하는 것으로, 예를 들어 리소스 URL을 입력할 때 다음 문자를 자동 제안하는 것입니다. SK에서 지원해야 할 개념이 아니며, SK를 사용하여 구축된 클라이언트가 이를 구현할 수 있습니다. |
| [Progress](https://spec.modelcontextprotocol.io/specification/2025-03-26/basic/utilities/progress/) | 미매핑 | MCP의 진행률은 장기 실행 작업의 진행 상황을 보여주는 것으로, SK에서 지원해야 할 개념이 아니며, SK를 사용하여 구축된 클라이언트가 이를 구현할 수 있습니다. |

## 설계 - 서버로서의 Semantic Kernel
이는 Semantic Kernel이 서버 역할을 하여 Kernel 및/또는 Agent의 기능을 호스트에 노출할 수 있기를 원한다는 것을 의미합니다.

### 개념 매핑 - 서버로서의 Semantic Kernel
| MCP 개념 | Semantic Kernel 개념 | 설명 |
| ----------- | ---------------------- | ----------- |
| [Server](https://modelcontextprotocol.io/docs/concepts/architecture) | Kernel/Agent | 서버는 관련된 함수의 집합으로 노출되므로, 단일 Kernel 또는 Agent를 MCP 서버로 노출할 수 있으며, 이는 호환되는 모든 호스트에서 소비될 수 있습니다. |
| [Resources](https://modelcontextprotocol.io/docs/concepts/resources) | 불명확 | 리소스는 매우 일반적인 개념이므로 어떤 하나의 SK 개념에는 맞을 수 있지만 전부는 아닙니다. 추가 조사가 필요합니다. |
| [Prompts](https://modelcontextprotocol.io/docs/concepts/prompts) | PromptTemplate | 프롬프트는 SK 서버 개발자가 사용자에게 해당 서버를 활용하기 위한 더 쉬운 진입점을 제공하기 위해 만들 수 있는 기능으로, 정의된 매개변수로 채워지는 단일 문장이거나 특정 결과를 시작하기 위해 설계된 대화를 시뮬레이션하는 일련의 메시지일 수 있습니다. 이는 PromptTemplate에 매핑되지만, 출력이 PromptMessages 목록(대략 ChatMessageContents 목록에 해당)이어야 하므로 일반적인 방식으로 이를 가능하게 하기 위한 작업이 필요합니다. 이 경우 클라이언트가 인수 집합을 제공하여 프롬프트를 요청하고, SK가 이를 렌더링하여 ChatMessageContent 목록으로 변환한 다음 MCP PromptMessages 목록으로 변환합니다. |
| [Tools](https://modelcontextprotocol.io/docs/concepts/tools) | Function | 도구는 서버 개발자가 사용자에게 서버의 특정 기능을 활용할 수 있게 만드는 기능입니다. 이는 Semantic Kernel의 함수에 매핑되며, 가장 일반적인 사용 방법은 함수 호출을 통한 것이므로 잘 매핑됩니다. listChanged 이벤트의 발생을 포함해야 합니다. |
| [Sampling](https://modelcontextprotocol.io/docs/concepts/sampling) | 불명확 | 샘플링은 서버가 클라이언트를 통해 LLM 완성을 요청할 수 있게 하는 강력한 MCP 기능으로, 보안과 개인정보를 유지하면서 정교한 에이전트 동작을 가능하게 합니다. 즉, SK 서버가 프롬프트를 렌더링한 다음 클라이언트에 LLM을 사용하여 완성하도록 요청하는 것을 의미합니다. 이는 SK의 핵심이므로 매핑이 필요하지 않을 수 있으며, LLM과 직접 상호작용하지 않는 MCP 서버에 주로 유용합니다. |
| [Roots](https://modelcontextprotocol.io/docs/concepts/roots) | 불명확 | Roots는 서버가 작동할 수 있는 경계를 정의하는 MCP의 개념입니다. 클라이언트가 서버에 관련 리소스와 위치에 대해 알려주는 방법을 제공하므로, SK는 현재 컨텍스트의 `roots`를 사용하는 서버에 보내야 하지만, 현재로서는 이를 매핑하는 방법이 불명확합니다. |
| [Transports](https://modelcontextprotocol.io/docs/concepts/transports) | 언어별 | Python의 경우, SDK가 상호작용을 통합한 다음 전송 타입 중 하나로 호스팅하므로, SK 자체에서 이를 지정할 필요가 없습니다. |
| [Completion](https://spec.modelcontextprotocol.io/specification/2025-03-26/server/utilities/completion/) | 미매핑 | MCP의 완성은 입력 중 사용자 입력을 완성하는 것으로, 예를 들어 리소스 URL이나 프롬프트 참조를 입력할 때 다음 문자를 자동 제안하는 것입니다. 프롬프트와 리소스에 대해 어떤 종류의 지원을 할 것인지에 따라 다르지만, 지원하는 경우 기본적으로(OOTB) 완성도 지원해야 합니다. |
| [Logging](https://spec.modelcontextprotocol.io/specification/2025-03-26/server/utilities/logging/) | 내장 로거 | MCP 로깅은 클라이언트와 서버 간의 상호작용을 로깅하는 방법으로, 기본적으로 로깅 핸들러를 추가하여 클라이언트/호스트가 설정하고 변경할 수 있어야 합니다. |
| [Progress](https://spec.modelcontextprotocol.io/specification/2025-03-26/basic/utilities/progress/) | 미매핑 | MCP의 진행률은 장기 실행 작업의 진행 상황을 보여주는 것으로, 에이전트나 프로세스에서 더 복잡한 장기 실행 작업을 수행할 때 흥미로울 수 있어 클라이언트에 업데이트를 제공하면 경험이 향상됩니다. 구현 방법이 불명확합니다. |
