# n8n 소개 및 로컬 설치 가이드

> 오픈소스 워크플로우 자동화 플랫폼 n8n의 개요와 macOS에서 Docker로 셀프호스팅하는 방법을 정리합니다.

---

## 1. n8n이란?

**n8n**은 오픈소스 **워크플로우 자동화 플랫폼**입니다. 코드 없이(또는 필요할 때 코드로) 다양한 앱과 서비스를 연결하여 업무를 자동화할 수 있는 도구입니다. 이름은 "**n**odematio**n**"(nodemation)의 줄임말로, 독일 베를린에서 시작되었습니다.

### 핵심 특징

#### 1) Fair-Code 라이선스 모델
- **Sustainable Use License** 기반의 오픈소스
- 완전한 MIT/Apache 같은 OSS는 아니지만, **소스 코드 공개 + 자체 호스팅 무료**
- Zapier, Make(구 Integromat)와 달리 **셀프호스팅이 가능**한 것이 최대 장점

#### 2) 노드 기반 시각적 워크플로우
- 브라우저에서 드래그 앤 드롭으로 워크플로우 구성
- **400개 이상의 내장 통합 노드** 제공 (Slack, Gmail, Notion, GitHub, OpenAI, Postgres 등)
- 각 노드는 "트리거 → 처리 → 출력" 흐름으로 연결

#### 3) 하이브리드 접근 (No-code + Code)
- 기본은 노코드 GUI
- 필요할 때 **JavaScript/Python 코드 노드**로 커스텀 로직 삽입 가능
- HTTP Request 노드로 어떤 REST API든 호출 가능

## 2. 주요 사용 사례

| 분야 | 예시 |
|------|------|
| **데이터 ETL** | DB → API → 스프레드시트 동기화 |
| **업무 자동화** | 이메일 수신 → 분류 → Slack 알림 → Notion 저장 |
| **AI 에이전트** | LangChain 노드로 LLM 워크플로우 구성 |
| **DevOps** | GitHub Webhook → CI 트리거 → 결과 리포팅 |
| **마케팅** | 리드 수집 → CRM 등록 → 개인화 이메일 발송 |

---

## 3. AI/LLM 통합

n8n은 최근 **AI 에이전트 빌더**로 포지션을 강화하고 있습니다.

- **LangChain 통합 노드** (Agent, Chain, Memory, Vector Store)
- OpenAI, Anthropic, Ollama, Hugging Face 등 LLM 프로바이더 노드
- RAG 파이프라인, 챗봇, 자동화 에이전트를 시각적으로 구성 가능

## 4. Zapier / Make와의 비교

| 항목 | n8n | Zapier | Make |
|------|-----|--------|------|
| **셀프호스팅** | ✅ 가능 (무료) | ❌ 불가 | ❌ 불가 |
| **가격 모델** | 실행 수 무제한(셀프) | 작업 수 과금 | 연산 수 과금 |
| **코드 확장** | ✅ 강력 | 제한적 | 제한적 |
| **복잡한 로직** | 우수 (분기/반복/에러처리) | 단순 편향 | 중간 |
| **학습 곡선** | 다소 가파름 | 쉬움 | 중간 |

## 5. 언제 n8n을 선택할까?

**적합한 경우**

- 민감한 데이터를 **외부 SaaS로 보내기 어려운** 기업 환경
- 많은 실행 건수로 Zapier 요금이 부담스러운 경우
- 복잡한 분기/에러 처리/커스텀 코드가 필요한 워크플로우
- AI 에이전트를 **시각적으로 프로토타이핑**하고 싶을 때

**부적합한 경우**

- 인프라 관리 부담을 지고 싶지 않은 경우 → Zapier/Make Cloud가 편함
- 초간단 2-step 연동만 필요한 경우 → 오버스펙

## 6. macOS에서 Docker로 로컬 설치하기

### 사전 준비
- Docker Desktop 설치 및 실행
  ```bash
  # Docker Desktop 실행
  open -a Docker
  ```

### 설치 명령
```bash
docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 5678:5678 \
  -v ~/.n8n:/home/node/.n8n \
  -e GENERIC_TIMEZONE="Asia/Seoul" \
  -e TZ="Asia/Seoul" \
  docker.n8n.io/n8nio/n8n
```

### 옵션 설명

| 옵션 | 의미 |
|------|------|
| `-d` | 백그라운드 실행 |
| `--name n8n` | 컨테이너 이름 지정 |
| `--restart unless-stopped` | Docker 재시작 시 자동 기동 |
| `-p 5678:5678` | 호스트의 5678 포트를 컨테이너에 매핑 |
| `-v ~/.n8n:/home/node/.n8n` | 데이터 영속화 (SQLite DB, 자격증명 등) |
| `-e GENERIC_TIMEZONE` / `-e TZ` | 타임존을 한국 시간으로 설정 |

### 접속

브라우저에서 **http://localhost:5678** 로 접속한 뒤, 첫 화면에서 Owner 계정(이메일 + 비밀번호)을 생성합니다.

## 7. 자주 쓰는 관리 명령어

```bash
# 로그 실시간 확인
docker logs -f n8n

# 중지 / 시작 / 재시작
docker stop n8n
docker start n8n
docker restart n8n

# 업데이트 (최신 이미지로)
docker pull docker.n8n.io/n8nio/n8n
docker stop n8n && docker rm n8n
# 이후 설치 명령 재실행 → ~/.n8n 볼륨 덕분에 데이터 유지됨

# 컨테이너 완전 삭제 (데이터는 ~/.n8n 에 남음)
docker stop n8n && docker rm n8n
```

## 8. 프로덕션 배포 시 추가 고려사항

로컬 실습이 아닌 실제 서비스로 운영한다면 다음 항목을 추가로 설정하는 것이 좋습니다.

- **데이터베이스**: SQLite 대신 PostgreSQL 사용 (`DB_TYPE=postgresdb`)
- **암호화 키 고정**: `N8N_ENCRYPTION_KEY` 환경 변수 지정 (자격 증명 암복호화용)
- **HTTPS**: Nginx, Caddy, Traefik 등 리버스 프록시로 TLS 종단 처리
- **외부 URL**: `WEBHOOK_URL`, `N8N_HOST` 설정으로 Webhook 공개 주소 지정
- **백업**: `~/.n8n` 디렉토리와 Postgres 덤프를 주기적으로 백업
- **인증 강화**: SSO(SAML/OIDC) 또는 Basic Auth 활성화
