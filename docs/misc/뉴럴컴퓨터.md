# 컴퓨터를 쓰는 AI에서, 스스로가 컴퓨터가 되는 AI로: '뉴럴 컴퓨터'의 등장

> **한 줄 요약:** 메타에서 뉴럴 컴퓨터(Neural Computers)라는 새로운 개념을 발표했습니다.

---

## 1. 서론: 우리가 알던 '컴퓨터'의 개념이 흔들리고 있습니다

지난 수십 년간 우리에게 '컴퓨터'는 일을 처리하기 위한 가장 중요한 매체였습니다. 최근 AI는 이 매체의 사용법을 빠르게 익히고 있습니다. 초기 AI가 그저 질문에 답하는 챗봇에 머물렀다면, 이제는 도구를 호출하고(Tool Use), 인터페이스를 직접 조작하며 실제 업무 흐름의 중심부로 진입하고 있습니다.

하지만 여기서 우리는 더 근본적인 질문을 던져야 합니다. 우리는 단순히 AI가 컴퓨터를 더 잘 '사용'하기를 원할까요, 아니면 AI 자체가 하나의 새로운 '컴퓨터'가 되기를 원할까요? 연구자 밍천 주게(Mingchen Zhuge)는 인공지능이 기존 시스템을 활용하는 단계를 넘어, 기계의 실행 환경(Runtime) 자체를 책임지는 **'뉴럴 컴퓨터(Neural Computer, NC)'** 라는 개념을 제시했습니다. 이는 기술의 단순한 진보가 아닌, 기계라는 형태의 근본적인 재정의를 예고합니다.

## 2. 에이전트를 넘어 '런타임'을 장악하는 AI

기존의 AI 에이전트와 뉴럴 컴퓨터의 차이는 **'책임의 소재'** 에 있습니다. 에이전트가 기존 운영체제 위에서 도구를 빌려 쓰는 '숙련된 사용자'라면, 뉴럴 컴퓨터는 기계의 실행 환경인 '런타임(Runtime)' 그 자체가 되려 합니다. 이는 소프트웨어 스택과 제어 계층에 분산되어 있던 시스템의 책임이 모델 내부로 이동하는 **'시스템 책임의 이주(Migration of system responsibilities)'** 현상입니다.

전통적인 시대의 관계가 '인간 -> 컴퓨터'였고, 에이전트 시대가 '인간 -> 에이전트 -> 컴퓨터'의 구조였다면, 뉴럴 컴퓨터 시대에 인간은 기계의 런타임을 직접 마주하게 됩니다. 저자는 이를 이미 많은 이들이 직감하고 있는 **'사전 합의(Pre-consensus)'** 단계라고 설명합니다.

> "진정한 핵심은 모델이 기계 자체의 런타임에 속해 있던 책임 중 일부를 넘겨받을 수 있느냐는 점입니다."
>
> *(The real question is whether a model can take over some of the responsibilities that still belong to the machine's own runtime.)*

## 3. 이제는 소프트웨어가 아니라 '능력(Capability)'을 설치합니다

뉴럴 컴퓨터 시대에는 '프로그래밍'이라는 단어의 의미가 완전히 바뀝니다. 지금까지는 개발자가 코드를 작성하고 컴파일하여 소프트웨어를 설치했다면, NC 환경에서는 사용자의 지시, 시연(Demonstration), 그리고 상호작용의 흔적 자체가 기계에 직접 주입되는 **'설치 가능한 능력 객체(Capability Object)'** 가 됩니다.

이 과정에서 NC는 단순한 동물적 지각을 넘어, 이산적이고 희소하며 국부적으로 검증 가능한 'NAND 스타일의 논리 구조'를 닮아갑니다. 특히 주목할 점은 **'재귀적 자기 개선(Recursive Self-Improvement)'** 입니다. 인간이 잠든 사이에도 NC는 내부적인 셀프 플레이(Self-play)와 테스트, 압축 과정을 통해 스스로 기능을 최적화하고 진화합니다. 즉, 사용자가 기계와 상호작용할수록 기계는 그 경험을 학습하여 내부 실행 구조를 스스로 재구성하는 것입니다.

## 4. 완벽한 뉴럴 컴퓨터(CNC)를 위한 4가지 조건

단순한 모델을 넘어 **'완벽한 뉴럴 컴퓨터(Completely Neural Computer, CNC)'** 로 기능하기 위해서는 다음 네 가지 공학적 요건이 반드시 충족되어야 합니다.

- **튜링 완전성(Turing complete)**: 단순히 다양한 작업을 하는 것을 넘어, 원칙적으로 모든 일반 계산을 수행할 수 있어야 합니다. 공학적으로는 메모리와 컨텍스트가 확장됨에 따라 더 길고 복잡한 알고리즘 프로세스를 안정적으로 유지할 수 있는지가 핵심 시험대가 됩니다.
- **범용 프로그래밍 가능성(Universally programmable)**: 입력이 일회성 행동에 그치지 않고, 나중에 다시 호출할 수 있는 루틴이나 내부 실행기로서 런타임에 '설치'되어야 합니다. 즉, 능력이 런타임 내에 유지되고 재사용 가능해야 합니다.
- **행동 일관성(Behavior-consistent)**: 명시적인 업데이트 없이는 기계의 행동이 변하지 않아야 합니다. 실행 과정을 추적하고 실패 시 재현(Replay) 및 롤백(Rollback)할 수 있는 관리 능력이 필수적입니다.
- **머신 네이티브 세만틱스(Machine-native semantics)**: 기존 컴퓨터 방식을 흉내 내는 것이 아니라, 신경망 고유의 구성(Composition), 라우팅(Routing), 연속적인 상태 변화를 통한 고유의 프로그래밍 문법을 형성해야 합니다.

## 5. 현실로 다가온 증거들: CLI에서 GUI까지

이러한 비전은 이미 구체적인 프로토타입 실험을 통해 그 가능성을 입증하고 있습니다.

- **CLIGen (터미널의 재구성)**: 비디오 생성 모델인 Wan2.1을 활용하여 약 1,100시간의 터미널 데이터를 학습시킨 결과, 기계는 터미널의 색상 변화, 커서의 움직임, 로그 스크롤 등 복잡한 텍스트 인터페이스를 사실적으로 렌더링했습니다. 이는 기계가 런타임의 외형과 리듬을 학습하는 '컴퓨터를 향한 모방 게임'에서 승리할 수 있음을 보여줍니다.
- **GUIWorld (그래픽 환경 제어)**: 마우스 클릭과 타이핑이 인터페이스 상태를 어떻게 변화시키는지 실험한 결과, 'Model 4 (내부 교차 주의 집중, Action cross-attention inside each block)' 설계가 가장 효과적이었습니다. 이는 행동 정보를 모델의 중추(Backbone) 깊숙이 주입함으로써 AI가 화면의 변화를 능동적으로 제어할 수 있음을 증명했습니다.

## 6. 미래의 하드웨어는 '회로'와 닮아갈 것입니다

뉴럴 컴퓨터가 성숙해짐에 따라 하드웨어 아키텍처 역시 거대한 전환을 맞이할 것입니다. 현재의 거대 언어 모델(Dense LLM)이 10억~10조(1B-10T) 파라미터 규모에서 모든 데이터를 빽빽하게 처리한다면, 미래의 CNC는 10조~1,000조(10T-1000T) 규모의 더 희소하고(Sparse), 주소 지정이 가능한(Addressable) 기질로 진화할 것입니다.

최근 OpenAI의 '가중치 희소 트랜스포머(Weight-sparse transformers)' 연구에서 보듯, 미래의 하드웨어는 특정 뉴럴 루틴을 필요할 때만 호출하고 연결하는 '회로(Circuit)'와 같은 구조를 띠게 됩니다. 이는 하드웨어가 단순히 모델을 구동하는 판을 넘어, 모델의 실행 구조에 맞춰 **'라우팅(Routability)'이 가능한 형태** 로 재편됨을 의미합니다.

## 7. 결론: 우리가 다시 정의해야 할 '컴퓨터'라는 단어

뉴럴 컴퓨터는 단순한 기술적 유행이 아닙니다. 하드웨어, 소프트웨어, 그리고 인간이 기계와 맺는 관계 전체를 재편하는 거대한 **패러다임 시프트** 입니다. 이제 컴퓨터는 우리가 작성한 코드를 수동적으로 실행하는 상자가 아니라, 우리의 경험을 학습하고 스스로 능력을 축적하며 진화하는 능동적인 런타임으로 탈바꿈하고 있습니다.

우리는 이제 스스로에게 근본적인 질문을 던져야 합니다.

> "미래에 당신이 사용할 기계는 당신이 설치한 코드를 실행하는 기계입니까, 아니면 당신의 경험을 학습하여 스스로 진화하는 런타임입니까?"

## 초보자를 위한 부연설명

이 문서에 등장하는 주요 용어와 개념을 쉽게 풀어 설명합니다.

### 런타임(Runtime)

프로그램이 실제로 실행되는 환경을 말합니다. 비유하자면, 요리사가 요리를 하는 '주방' 자체에 해당합니다. 기존에는 운영체제(Windows, macOS 등)가 이 주방 역할을 했는데, 뉴럴 컴퓨터는 AI 모델 자체가 주방이 되겠다는 개념입니다.

### 튜링 완전성(Turing Completeness)

이론적으로 어떤 계산이든 수행할 수 있는 능력을 뜻합니다. 쉽게 말해 "충분한 시간과 메모리만 있으면 세상의 모든 계산 문제를 풀 수 있다"는 의미입니다. 계산기가 덧셈뺄셈만 할 수 있다면 튜링 완전하지 않지만, 범용 컴퓨터는 어떤 프로그램이든 실행할 수 있으므로 튜링 완전합니다.

### 에이전트(Agent)

사용자를 대신해서 스스로 판단하고 행동하는 AI 프로그램입니다. 비서가 상사의 지시를 받아 이메일을 보내고, 일정을 잡고, 자료를 찾아오는 것처럼, AI 에이전트는 도구를 사용하고 여러 단계의 작업을 자동으로 수행합니다.

### 희소(Sparse)

'빽빽하지 않고 듬성듬성한' 구조를 의미합니다. 교실에 100개 책상이 있는데 10명만 앉아 있다면 '희소한' 상태입니다. AI 모델에서 희소하다는 것은 전체 파라미터 중 필요한 부분만 활성화하여 효율적으로 동작한다는 뜻입니다. 반대 개념이 Dense(빽빽한)입니다.

### 라우팅(Routing)

데이터나 신호를 적절한 경로로 보내주는 것입니다. 택배 물류센터에서 각 택배를 목적지별로 분류해서 올바른 트럭에 실어 보내는 과정과 비슷합니다. AI 모델에서는 입력 데이터를 처리에 적합한 내부 경로(전문화된 부분)로 보내주는 과정을 의미합니다.

### 컨텍스트(Context)

AI가 한 번에 처리할 수 있는 정보의 범위를 말합니다. 사람이 책을 읽을 때 한 번에 기억하며 읽을 수 있는 분량이라고 생각하면 됩니다. 컨텍스트가 클수록 더 많은 정보를 동시에 고려하여 판단할 수 있습니다.

### 셀프 플레이(Self-play)

AI가 스스로를 상대로 연습하며 실력을 키우는 방법입니다. 바둑을 혼자서 흑과 백을 번갈아 두면서 실력을 높이는 것과 같습니다. AlphaGo가 이 방법으로 인간을 넘어선 것이 대표적인 사례입니다.

### 롤백(Rollback)

문제가 생겼을 때 이전의 정상 상태로 되돌리는 것을 말합니다. 게임에서 '세이브 포인트'로 돌아가는 것과 같습니다. 소프트웨어 업데이트 후 오류가 발생하면 이전 버전으로 되돌리는 것이 롤백의 일상적인 예시입니다.

### Dense LLM

모든 파라미터가 빈틈없이 가동되는 대규모 언어 모델입니다. 회사의 모든 직원이 모든 프로젝트에 동시 투입되는 것과 비슷합니다. 강력하지만 비효율적일 수 있어서, 앞으로는 필요한 부분만 활성화하는 희소(Sparse) 모델로 진화할 것으로 전망됩니다.

### 파라미터(Parameter)

AI 모델이 학습을 통해 조정하는 내부 숫자값들입니다. 라디오의 다이얼(주파수 조절 노브)과 비슷합니다. 다이얼을 정밀하게 조절해야 원하는 방송이 또렷하게 들리듯, 파라미터를 정밀하게 조정해야 AI가 정확한 결과를 냅니다. GPT-4 같은 모델은 이런 다이얼이 수천억 개 이상 있다고 볼 수 있습니다.
